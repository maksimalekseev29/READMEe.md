# Лабораторная работа №3 — Модуль HabitModule (проект «HabitTracker»)

## 1. Выбранные пользовательские истории и модуль.
**История пользователя:** Как пользователь, я хочу фильтровать свои привычки по категориям, чтобы видеть только нужные мне в данный момент. 
**Модуль:** `HabitModule`, метод `get_filtered_habits(category, only_available)`. 
**Зона ответственности:** содержание списка привычек, фильтрация по категориям (здоровье, спорт, ...) и наличию (активности).

## 2. Модульная архитектура (клиент-сервер)

* Клиент отправляет запрос (например, `GET /habits?category=спорт&only_available=true`).
* API Gateway маршрутизирует запросы в нужный модуль.
* Модули независимы, общаются только через утверждённые интерфейсы.
* `HabitModule` зависит от модуля стриков, поэтому используется Стаб `StreakStub.is_streak_active()` (всегда True).

## 3. Интерфейсная модуляция

| Параметр | Тип | Я |
| :--- | :--- | :--- |
| `category` | `str` или `None` | Одно из: здоровье, спорт, развитие, работа, быт. `None` — все. Регистры и пробелы по краям игнорируются. |
| `only_available` | `bool` | `True` — только активные привычки. |
| Возвращаемый формат | `list[dict]` | Копии привычек под фильтром. |
| Ошибки | `HabitError` | Неверный тип, неизвестная, пустая или слишком длинная (>50) категория. |

Данные привычки проверяются при составлении модуля: все поля обязательны, время выполнения (`target_time`) должно быть в формате `HH:MM` (от 00:00 до 23:59), `id` уникально.
